# 面向 Vant 项目的小米广告 SDK 设计建议

## 背景

当前项目基于 Vant 组件库开发移动端 H5 / 小程序界面，需要接入小米广告 SDK 以实现以下目标：

1. **商业化变现需求**  
   - 通过开屏广告、信息流广告、激励视频广告等形式增加应用收益。  
   - 在不显著影响用户体验的前提下，提高广告展示与点击转化率。

2. **统一的广告接入能力**  
   - 项目中可能会接入多家广告平台（如小米、腾讯、字节等），小米广告 SDK 是其中一环。  
   - 如果直接在业务页面中散落广告调用代码，会导致耦合严重、维护成本高。  
   - 需要抽象统一的“广告服务层”和“通用广告组件”，使小米广告 SDK 成为可替换的底层实现之一。

3. **兼容 Vant UI 与现有交互逻辑**  
   - 项目已有大量基于 Vant 的页面布局和交互（如 Dialog、Popup、List、Tab、PullRefresh 等）。  
   - 广告位需要与这些组件自然融合：  
     - 信息流广告要能插入到基于 `van-list` 或自定义列表结构中。  
     - Banner / 插屏广告需要与 Vant 的弹框、遮罩及路由切换节奏保持一致。  
   - 为避免侵入式改动，应通过 Vant 风格的“广告组件”来承载广告，而不是直接在业务代码里操作 DOM/原生 API。

4. **性能与体验要求**  
   - 在移动端弱网场景中，广告请求与渲染不能明显拖慢页面加载。  
   - 与 Vant 的懒加载、骨架屏、图片占位策略相协调，避免“布局抖动”和白屏。  
   - 对于首屏和关键业务流程（如下单、支付、认证等），需要严格控制广告展示频率与时机。

5. **数据统计与策略调优**  
   - 广告相关事件（曝光、点击、关闭、激励达成等）需要统一上报，与现有埋点体系整合。  
   - 后续希望根据数据进行 A/B 测试：  
     - 不同广告位布局（列表前几条、列表中部、详情页底部等）；  
     - 不同展示频率、加载时机；  
     - 不同广告样式与 Vant 主题配色适配情况。  
   - 因此在设计之初就需要预留事件上报和配置化策略的扩展能力。

6. **隐私合规与开关控制**  
   - 小米广告 SDK 可能涉及设备信息、行为数据收集，需要符合相关隐私合规要求。  
   - 项目中要提供统一的广告开关与隐私设置入口，支持：  
     - 按用户地区、版本或渠道动态控制是否启用广告；  
     - 在用户不同授权状态下选择性启用部分广告类型。  
   - 对于 Vant 页面来说，应当通过统一的“广告服务配置”来控制广告组件的渲染与否，而不是在页面里写死逻辑。

在上述背景下，面向 Vant 项目的小米广告 SDK 设计应重点关注：

- 将小米广告 SDK 封装为**统一的广告服务模块**，屏蔽平台细节。  
- 提供一组**与 Vant 风格一致的广告 UI 组件**（例如 `<AdBanner>`, `<AdFeedItem>`, `<AdRewardDialog>` 等），方便在各业务页面复用。  
- 支持**配置化与可插拔**的广告策略（频控、位置、样式、开关），以便后续迭代优化。  
- 与现有的埋点系统、权限与隐私管理体系良好集成，保证可观测性与合规性。

后续设计建议部分可以从“架构设计”、“组件封装”、“事件埋点与配置”、“与 Vant 的交互细节”几个维度展开，逐步细化具体实现方案。
